Exam trap: the middle column

"Private repository without a GHAS license" is the column the exam targets most. Most features are not available there — only Dependabot alerts and the dependency graph. If a question scenario says "private repo, no advanced security license", any answer involving secret scanning, code scanning, push protection, or Dependency Review is wrong. Those features simply don't exist in that scope.

Why public repos get so much for free

GitHub makes GHAS-class security features free on public repositories. Why? Two reasons matter for the exam: open source security has spillover effects (a vulnerability in a popular OSS library hurts every project that uses it), and visibility is already public (a secret leaked in a public repo is already a serious incident regardless of whether GitHub scans for it).

On public repos, by default

  • Secret scanning alerts: on automatically
  • Push protection for partner patterns: on by default since 2024
  • Dependency graph: on automatically
  • Dependabot alerts: on automatically
  • Code scanning (CodeQL): available but requires you to set up the workflow
  • Dependency Review: available on every PR

On private repos without GHAS

  • Secret scanning alerts: not available
  • Push protection: not available
  • Dependency graph: available but must be enabled (not on by default)
  • Dependabot alerts: available (free for everyone)
  • Code scanning: not available
  • Dependency Review: not available
The pattern to memorize

Public repos get almost everything for free. Private repos without a GHAS license get only Dependabot. Buying GHAS for a private repo brings it up to parity with public repos and adds custom secret patterns on top.

Two adjacent features the exam will absolutely test

Inside the Dependabot family there are two features that watch dependencies — but they intervene at different moments. Knowing which is which is one of the most common Domain 1 exam questions.

Dependabot alerts Dependency Review
When does it intervene? Continuously — after a dependency turns vulnerable (even if it was added long ago) On every pull request — before the merge happens
What does it scan? Existing dependencies declared in the repo's manifest files Only the dependencies being added or changed in the PR diff
Where does it surface? Security tab → Dependabot alerts PR check status + diff annotations on the PR itself
Can it block? No — it alerts; the developer decides what to do Yes — if configured as a required check, vulnerable dependencies block the merge
Free on private repos? Yes, for everyone No — requires GHAS
Exam trap: the verb tells you which one

Look for the timing word in the question. "Before merge" → Dependency Review. "Already in the repo" or "turned vulnerable" or "continuously monitors" → Dependabot alerts. The two will appear as adjacent answer options on at least one question — bet on it.
