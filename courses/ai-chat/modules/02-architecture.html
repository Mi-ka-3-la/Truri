The Architecture

Seven components. Three LLM providers. A dynamic tool registry. An artifact engine. Here is how it all connects.

The tech stack, layer by layer

React Frontend (avise-web)

TypeScript + React. The AIChat component family lives in src/components/AIChat/. Uses TanStack Query mutations for sending messages. Artifact cards live in AiChatItem/artifacts/ — each artifact type (journalEntry, schedule, accounts, table) has its own renderer and action handler.

Express Controller (avise-api)

aiController.ts is the single entry point. It parses multipart form data for file uploads, validates the request, and calls createOrContinueConversation(). Route: POST /v1/companies/:companyId/ai/chat.

Conversation Loop (ai/index.ts)

The engine. An iterative for loop runs up to MAX_TOOL_CALLS + 100 iterations. Each iteration sends messages to the LLM, processes tool calls, saves to the database, and either loops again or terminates.

LLM Provider Abstraction (providers/)

BaseAiProvider defines the interface: sendMessageToProvider(), uploadFile(), generateEmbedding(). Three concrete implementations: OpenAI (default), OpenRouter (multi-model), OpenAI-Compatible (custom endpoints). Provider selected per-request via validated overrides.

PostgreSQL + Conversation Storage

Conversations and messages persisted via ai/data/conversations.ts. Artifacts in ai/data/artifacts.ts. File uploads to S3; metadata to the file library. Context is cleaned of S3 details and file content before each database write.

Provider selection is per-request, not per-server

An overrides object in the request body can switch the model or provider for a single conversation. sanitizeOverrides() validates these before use — only allowlisted models are accepted. This scopes the change to one request only.

How MCP tools get registered at startup

A
App Startup

AI is enabled (OpenAI key present). Calling McpServerAdapter.initializeMcpServers(failFast: false). If MCP servers fail, the app continues with built-in tools only.

M
McpServerAdapter

Reading MCP_SERVERS config. Creating a dedicated Client per server. Connecting via stdio / sse / websocket as configured.

S
MCP Server

Connected. Here are my tools: [list of tools with JSON schema definitions]. I will send a tools/list_changed notification if my tools update.

M
McpServerAdapter

Converting MCP JSON schemas to our GenericTool format. Prefixing names with myserver__ to avoid conflicts. Storing in static registry. Done.

L
Chat Request (later)

New conversation. Building ToolRegistry with 20 built-in tools. Calling McpServerAdapter.registerMcpTools(registry, false) — MCP tools added. Total tools available to LLM: 23.
