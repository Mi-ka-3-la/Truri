01

What is Flux Analysis?

The financial X-ray that shows you not just where your numbers landed, but how far they moved — and why that matters.

You already know what this is — you just didn't have a name for it

The question everyone asks

"Revenue went up $40k this month — but is that normal? Was it higher or lower than last month?"

Flux Analysis is the answer

It places two periods side by side — current vs. prior — and calculates exactly how much each account moved, in dollars and in percentage.

Every accountant does this comparison mentally. Avise just automates it for every single account simultaneously and surfaces the ones that deserve attention.

Think: weather forecast vs. historical average

Today's temperature (current period) only means something when you compare it to last week or last year. Flux Analysis gives financial statements the same context — without it, a number is just a number.

Four columns. One complete picture.

Every row in the Flux Analysis table represents one account (like "Cash", "Revenue", or "Accounts Receivable"). The four dynamic columns always show the same structure:

1
Current period balance

What the account balance is for the period you selected — e.g., October 2024.

2
Prior period balance

What the same account showed in the comparison period — e.g., September 2024 (for Month over Month).

3
Amount Change ($ Change)

Current minus prior, in dollars. Positive = grew, negative = shrank. Simple arithmetic, no settings needed.

4
% Change

How big was the movement relative to where it started? $10k change is huge for a $20k account, trivial for a $10M account. The percentage puts it in context.

Two more columns that only appear if configured

A Status column (the task workflow badge) and an Explanation column appear only when a flux task has been created for that account. They're layered on top of the financial data — not part of the core report.

Three views, one concept

Flux Analysis comes in three flavours. Same core idea, different scope:

Balance Sheet Flux

Compares Assets, Liabilities & Equity between periods. Good for spotting large movements in cash, receivables, or debt.

Income Statement Flux

Compares Income, Expenses, and Net Income. Good for understanding revenue swings and cost changes month to month.

Single-Account Flux

Opens when you click into a specific account row. Shows a detailed breakdown — and uniquely, can pivot by dimension (e.g., break revenue down by Department).

Balance Sheet and Income Statement views are accessed via the sub-navigation at the top of the Flux Analysis page. Single-Account opens as a slide-over panel when you click any individual account row.

Picking Your Comparison Mode

Month over Month, Quarter over Quarter, Year over Year — not just cosmetic labels. Each one pulls different date ranges from the database.

Three lenses on the same data

Month over Month

Current month vs. the immediately prior month. Best for operational close reviews — "what changed this month?"

monthOverMonth

Quarter over Quarter

Current fiscal quarter vs. the prior fiscal quarter. Smooths out month-to-month noise for trends.

quarterOverQuarter

Year over Year

Current fiscal year-to-date vs. the same period last year. Best for seasonality-adjusted analysis.

yearOverYear
The comparison dropdown is feature-flagged

The feature flag additional-flux-report-types controls whether QoQ and YoY appear in the dropdown. When it is off, only Month over Month is available. Today this flag defaults to off, so most users only see the MoM option.

What actually happens when you pick a comparison

Your dropdown selection travels from the UI through the API to the backend, which uses it to decide which two date ranges to load from the database. Here's the conversation:

U
Your Browser (UI)

Report received. Rendering the table with column headers “October 2024”, “September 2024”, “Amount Change”, “% Change”. Done!

Quarter and Year comparisons use fiscal calendar, not calendar year

For QoQ and YoY, the backend doesn't use January 1 as the year start — it uses your company's configured fiscal year start. This ensures the quarters line up correctly for your business.

Month over Month: simplest case — compare to the immediately prior calendar month. Start and end dates come directly from the selected period's boundaries.

2

  return {
    compareTo: CompareToOptions.PreviousQuarter,
    startDate: formatDate(fiscalQuarterStartDate),
    endDate: formatDate(fiscalQuarterEndDate),
  };

Quarter over Quarter: the date range expands to cover the entire fiscal quarter. fiscalQuarterStartDate is computed using the company's fiscalYearStartMonth and fiscalYearStartDay settings. If your FY starts April 1, Q1 is April–June, not January–March.

3
case FluxComparison.yearOverYear:
  return {
    compareTo: CompareToOptions.PreviousYear,
    startDate: formatDate(fiscalYearStartDate),
    endDate: formatDate(fiscalYearEndDate),
  };

Year over Year: date range expands to the full fiscal year. The backend computes this YTD (year-to-date) range and compares it to the same YTD span in the prior fiscal year. So if you select October 2024, you get FY24 YTD (April–October) vs FY23 YTD (April–October).

Threshold alerts only work for Month over Month

The yellow alert icon (and the create-mom-flux-task feature) only fires when comparison is monthOverMonth. QoQ and YoY will never show threshold alerts, even if thresholds are configured in Settings. This is a hardcoded rule in the UI cell renderer.

03

The % Change Column

The formula is pure mathematics. It never looks at your settings. Here's exactly how it works — including the edge cases that surprise people.

One formula. Always the same.

The % Change column is computed by the backend for every account, every time. It uses one formula from avise-api/src/services/reports/financialStatements/shared/utils.ts:

CODE 
function percentChangeComparison(
  previousValue: number,
  currentValue: number
): number {
  if (previousValue === currentValue) return 0;
  if (previousValue === 0) {
    return currentValue > 0 ? -100 : 100;
  }
  return ((currentValue - previousValue) / previousValue) * 100;
}
PLAIN ENGLISH

Define a function that takes the prior period balance and the current period balance.

If nothing changed (both values identical), return 0%.

If the prior period was zero — we can't divide by zero — so return a fixed value of -100 or +100 instead.

Otherwise, standard formula: how much did it change, relative to where it started?

Division by zero is handled — not left as an error

When an account had no balance last period but has one now (a brand-new account, or seasonal activity), dividing by zero would produce infinity. The code caps this at -100 or +100 instead of crashing. You may notice “-100%” on newly active accounts — that's why.

Every edge case, explained

Here is what the formula produces for every scenario you might encounter:

Prior $100, Current $150 +50% — standard case. ((150-100)/100)×100 = 50.
Prior $100, Current $0 -100% — account went to zero. Fully decreased.
Prior $0, Current $50 -100% — no prior balance, can't compute real %. Shows -100 by convention (new activity).
Prior $0, Current $0 null — displayed as blank. The null result is filtered by Number.isFinite() in the legacy flux path and shows as an empty cell.
Prior $0, Current -$30 +100% — negative current, zero prior. Returns 100 (by convention).
Same values both periods 0% — equal values. Returns 0 before the division step runs.
Sign convention for credit-nature accounts

Accounts like Revenue, Liabilities, and Equity are credit-nature and are flipped (negated) for display. The % change itself is computed on the raw integer balances before any sign flip, so the percentage you see always reflects the true directional movement.

04

Threshold Settings

Settings → Task Accruals → Flux Threshold controls three completely separate things. Understanding which is which avoids a lot of confusion.

One settings panel. Three independent systems.

When you open Settings → Task Accruals → Flux Threshold for Auto-Review, you see three fields. People assume they all work together. They don't — each one controls a completely different part of the system:

% Change Threshold

Controls whether the yellow alert icon appears on the % Change column AND whether auto-review checks the percentage.

fluxPercentChangeThreshold — nullable, no default

$ Change Threshold

Controls whether the yellow alert icon appears on the $ Change column AND whether auto-review checks the dollar amount.

fluxBalanceChangeThreshold — nullable, no default

Days Before End of Period

Controls when flux tasks are created — how many days before the period ends do recurring flux tasks get auto-generated.

fluxDaysBeforePeriodEnd — default: 10
% column value, alert icon, and task creation are three independent systems

The % Change column always shows the calculated number — no setting affects it. The alert icon only appears if a threshold is set AND the create-mom-flux-task feature flag is on AND the comparison is Month over Month. Auto-review runs on its own schedule, separate from display. These three systems share the same settings input but execute independently.

The exact rules for the yellow alert icon

The alert icon (a yellow warning triangle) is the most visible consequence of threshold settings. Here is the complete list of conditions that must ALL be true for it to appear:

1
The create-mom-flux-task feature flag must be ON

If this flag is off (the current default), no alert icon ever appears — regardless of any settings.

2
Comparison must be Month over Month

Alert icons are hardcoded to only appear for the monthOverMonth comparison. QoQ and YoY never show alerts.

3
The relevant threshold must be set (non-null) in Settings

If % Change Threshold is null, the accountPercentChangeOverThreshold flag is never set by the backend. Same for $ Change Threshold.

4
The account's value must exceed the threshold (strictly >, not ≥)

The comparison is Math.abs(value) > threshold. An account exactly at the threshold does NOT trigger the alert.

5
“Hide Threshold Alerts” filter must be OFF

The filter bar has an option to hide alerts. If enabled, icons are suppressed in the UI even if all other conditions are met.

Empty Settings: what still happens vs what goes silent

Both fluxPercentChangeThreshold and fluxBalanceChangeThreshold have no database default — new companies get null. Here's the full impact:

% Change column value Always works. The formula runs on raw balances. Settings do not affect the number displayed.
Yellow alert icon Never appears. With null thresholds, the backend never sets the flag, so the icon has nothing to read.
Auto-review Off completely. If both thresholds are null, isAutoReviewFluxEnabled() returns false and the checker exits immediately.
Task creation timing Uses default: 10 days. fluxDaysBeforePeriodEnd has @default(10) in the database schema. Every new company gets 10 days silently.
The one hidden default: 10 days before period end

This is the only predefined rule that runs even when Settings is completely empty. The fluxDaysBeforePeriodEnd field in the database has @default(10), so flux recurring tasks are created 10 days before the period ends from day one — without the admin configuring anything. It lives in avise-domains/prisma/schema.prisma, line 242.

Exporting Your Flux Report

An Export button already exists — but it only produces XLSX for company flux. Here's the full picture of what's available today and where the gaps are.

The export map — who gets what today

Company Flux → XLSX

An “Export” button is already in the top-right corner of the Flux Analysis page. Clicking it downloads an Excel file with all visible accounts, balances, and changes.

EXISTS TODAY

Consolidation Flux → CSV

The Consolidation Flux Analysis page already has a CSV export. It downloads a comma-separated file with classification, account name, balances, % change, and $ change columns.

EXISTS TODAY

Company Flux → CSV

There is no CSV export for the main company-level Flux Analysis page (Balance Sheet or Income Statement). Only XLSX is available today.

NOT YET BUILT

Single-Account Flux → Any format

The drilldown panel for individual accounts (with the dimension pivot) has no export button. There is no export at all for single-account flux.

The same endpoint that serves the JSON report also serves the XLSX file — the format is decided by an HTTP header called Accept.

The same endpoint serves both the table and the download

There is no separate “export endpoint”. The GET /companies/:id/reports/flux/balance-sheet endpoint checks the Accept header and decides: if the browser wants Excel, it sends XLSX; otherwise it sends JSON for the table. This is the standard content negotiation pattern used across all reports in Avise.

What's in the XLSX file

The XLSX export from company flux includes more than the on-screen table. It includes task information too — because it uses a slightly older formatter that fetches tasks separately:

Current period balance Formatted as currency with the company's home currency symbol.
Prior period balance Same formatting. Column header uses the actual period display name (e.g., “September 2024”).
% Change Formatted as a percentage column, not a currency column. The XLSX cell is actually typed as percentage.
Amount Change ($ Change) Dollar delta between the two periods.
Status The task status (Prepared, Reviewed, etc.) for accounts that have a flux task. Blank for accounts without tasks.
Resolution Comment The explanation text entered when a flux task was prepared. Also blank if no task exists.

The CSV export for consolidation flux has slightly different columns: Classification, Sub-Classification, Account Type, Fully Qualified Account Name, Account Name, [Prior Period], [Current Period], % Change, Amount Change. No task columns — it's a pure financial export.
