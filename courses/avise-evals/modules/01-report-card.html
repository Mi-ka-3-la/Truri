The Report Card for AI

You built an AI accountant. How do you know if it's doing a good job?

You can chat with it in plain English and it will look up journal entries, propose amortization schedules, answer questions about your books — things that used to take minutes of clicking now take seconds of typing.

The Problem: AI Is Non-Deterministic

Unlike regular code — where the same input always produces the same output — AI is non-deterministic. Every time you call an LLM, you might get a slightly different response. So how do you check that the AI is doing its job correctly — at scale, across all edge cases, every time you change the code?

💡
The Core Insight

You can't unit-test AI the way you test regular code. Instead you run many real interactions against the real AI and score the responses. That's exactly what the evals system does.

This is where Evalite and Avise's evals SDK come in.

What Is an Eval? Think: a Report Card

A school report card works like this: a student (the AI) is given a task, they do their work, and a teacher (the scorer) grades the result. The grade is a number — 0 for fail, 1 for pass, or something in between for partial credit.

1
Give the AI a prompt

A natural-language instruction like "Show me journal entry #42" or "Create a 12-month amortization schedule for $12,000."

2
The AI responds

The real AI agent runs, calls its tools, and produces a response — just like a real user interaction.

3
Scorers grade the response

The response is checked against a list of expectations — did it mention the right account names? Did it produce the right artifact? Each check returns a score from 0 to 1.

4
Results are recorded

Evalite stores the scores and metadata so you can review them in a dashboard and track improvement over time.

Where to Find This in the Code

All the evals-related code lives in avise-api/evals/. Here is the layout:

evals/ All eval code lives here
sdk/ Avise's own toolkit — the building blocks used to write evals
index.tsThe evaluateAgent() function — the main entry point
metrics/All the scoring logic — StringMatch, ArtifactsExist, etc.
tasks/How to run the AI (stringInputTask is the most common)
utils/Helpers: parse tool calls, extract messages, etc.
evalsContext.tsThe EvalsContext class — loads test data from the DB
helpers.tsPre-built metrics for common checks (shouldHaveDisplayId, etc.)
findJeScenarios/Tests for the "find journal entry" feature
proposeScheduleScenarios/Tests for the "propose schedule" feature
guardrails/Tests that the AI obeys limits (e.g. no raw IDs in responses)
ℹ️
How to Run Evals

From the avise-api folder: pnpm evals to run once, pnpm evals:watch for live reload. Results appear in a local Evalite UI at localhost:3001.
