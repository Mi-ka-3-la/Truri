The ORM and cache sit between the server and the databases. The browser never talks to the databases directly — everything is mediated through the server layer.

Five characters, their personalities

🖥️
Your Browser (React)

Renders what you see. Built with React — a library that breaks the UI into reusable pieces called components.

⚡
Next.js Server

The invisible middleman. Next.js runs on the server, fetches data, applies logic, and builds pages before your browser ever sees them. It also holds the cache.

🔄
Prisma (ORM)

The translator. Prisma converts TypeScript queries into SQL and converts rows back into TypeScript objects.

🗄️
PostgreSQL (Main Database)

The warehouse. PostgreSQL stores every AI conversation ever recorded. The Trace Viewer only reads from it — nothing it does changes this data.

📝
SQLite (Notes Database)

The sticky-note wall. SQLite stores reviewer comments and maintains a full-text search index so keyword searches across all notes are instant.

What a "trace" actually looks like in code

The server assembles all the data for one conversation into a FullTrace object before sending it to the browser. Here is its shape, directly from types/index.ts:

CODE 

interface FullTrace {
  conversationId: string;
  title: string | null;
  user: {
    id: string;
    fullName: string;
    email: string;
  };
  messages: TraceMessage[];
}
PLAIN ENGLISH

An interface is a contract — it defines exactly what fields a FullTrace must contain.

Every conversation has a unique ID — like a receipt number.

The title is optional — conversations might never get named (hence "or null").

A nested object holding everything about the person who had this conversation...

...their internal user ID,

...their display name,

...and their email address.

A list (array) of every message in the conversation, in order — user, assistant, and tool messages all mixed together.

End of the contract.

💡
Interfaces are checkable promises

A TypeScript interface is a promise the compiler enforces. Any function that says it returns a FullTrace will fail to build if it omits any of these fields. This catches bugs before they ever reach the browser.

N

N

Cache miss. Prisma, I need conversation abc-123 with all messages, user info, and artifacts.

P

Translating that into SQL now... PostgreSQL, give me conversation abc-123 with JOINs on users and messages.

D

Found it. 47 messages, 12 tool calls, user is Sarah from Acme Corp. Returning all rows.

P
Prisma

Converted raw rows into a FullTrace TypeScript object. Handing it to Next.js.

N
Next.js Server

Got the FullTrace. Storing in cache for 2 minutes with tag "trace". Sending the page to the browser.

S
SQLite

Browser asked for notes on abc-123. Found 3 comments. Sending them to the Notes panel.

B
Browser

Page rendered, notes loaded. Everything visible. The whole trip took about 180ms.
