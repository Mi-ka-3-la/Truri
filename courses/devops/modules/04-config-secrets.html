Config, Secrets & Feature Flags

How 50+ environment variables are validated, how AWS Secrets Manager replaces GitHub Secrets, how Split.io gates features, and the facet pattern for multi-role services.

The config system — Joi validation per concern

Every config value is validated by Joi before the application starts. Config is split into domain-specific modules — one per external concern:

appConfigBasic app settings: NODE_ENV, port, frontend base URL, facet identifier.
emailConfigSES_DOMAIN, SKIP_EMAIL_SEND flag. Defaults to dev.avise.ai domain for dev.
knockConfigKNOCK_SECRET_KEY, KNOCK_SIGNING_KEY for Knock notification webhooks.
aiConfigOpenAI API key, model settings, MCP server configs, tool limits.
featureFlagsConfigSPLIT_API_KEY for Split.io SDK initialization.
datadogConfigDD_API_KEY, DD_VERSION, DD_ENV for DataDog APM and tracing.
prismaConfig / drizzleConfigDATABASE_URL, connection pool settings for PostgreSQL.
redisConfigRedis connection URL for BullMQ job queues.
awsConfigAWS region, S3 bucket name, SES settings.
authorizationConfigSpiceDB (Authzed) endpoint and credentials for the authorization service.
argoWorkflowConfigArgo Workflow server URL for submitting async jobs.
operationTrackingConfigS3 bucket for operation event storage.
Fail-fast in production, warn-and-continue in local dev

If a required config value is missing in production, the app crashes immediately with a clear error. In local dev, invalid config logs a yellow warning and continues — so developers can run the app without configuring every external service.

The facet pattern — one process, three roles

avise-api can run in three different facets using the same Docker image:

main

The REST API server. Handles HTTP requests from the frontend and external services. This is the default when AVISE_FACET is unset. Strict config validation — missing required env vars crash immediately.

bullmq

Background job processor for BullMQ queues. Runs tasks like email sending, task review checks, and file processing. Does not listen on a port.

workflow

Executes Argo Workflow scripts — long-running async jobs like bulk period open or schedule creation. Spun up by Argo as a Kubernetes pod, runs to completion, then terminates.

One image, many roles — a classic ops pattern

Rather than building three separate Docker images, the facet pattern reuses one image. Kubernetes runs different instances with different AVISE_FACET values. This keeps Docker build time and ECR storage low, and ensures all roles always run the same code version.

Feature flags — Split.io controls everything at runtime

Avise uses Split.io for feature flags on both backend and frontend. Flags are evaluated per-request, per-organization — no redeploy needed to change behavior.

A
API Startup

Initializing Split.io SDK with SPLIT_API_KEY. Connecting to Split.io servers asynchronously. The app continues starting up while SDK initializes.

C
Feature Flag Code

Request comes in. Calling FeatureFlagsClient.flagEnabledForOrganization('ai-complex-schedules', organizationId).

S
Split.io SDK

Looking up ai-complex-schedules for organization org-abc. Rule: ON for organizations in the early-access list. Result: on.

C
Feature Flag Code

Flag is ON. Including proposeMultiLineSchedule tool in the AI tool registry. If flag were OFF: tool would be deleted from availableTools before the conversation starts.

F
React Frontend

Frontend evaluates the same flag client-side via REACT_APP_SPLIT_CLIENT_SIDE_KEY. Shows or hides UI elements based on the flag value — no server round-trip needed for UI gating.
