Observability & External Services

DataDog for traces and RUM, Knock for notifications, QBO Sync for accounting data, Redis for job queues, SpiceDB for authorization, and MCP servers for AI tooling.

DataDog — traces, RUM, and source maps

APM Traces

The backend initializes dd-trace at startup (before any imports). Every HTTP request, database query, and external API call is traced automatically. Logs use facet tags to distinguish REST API, BullMQ, and workflow roles.

RUM

RUM is initialized in the React frontend using REACT_APP_DATADOG_RUM_APP_ID and REACT_APP_DATADOG_RUM_CLIENT_TOKEN. Frontend errors and performance data are correlated with backend traces.

Source Maps

The Amplify build uploads source maps to DataDog using DATADOG_SOURCE_MAP_UPLOAD_API_KEY. This lets DataDog translate minified production JavaScript errors back to the original TypeScript source code in error reports.

avise-shared-utils/src/logger/index.ts — Winston + DataDog JSON format
1
const logFormat =
  process.env["NODE_ENV"] === "production"
    ? winston.format.json()
    : winston.format.combine(
        winston.format.simple(),
        colorWinstonWithChalk,
      );

In production, logs output as JSON — DataDog can parse and index each field. In local dev, logs are colored terminal-friendly text. Same log calls, different output format.

const logger = winston.createLogger({
  level: process.env["LOG_LEVEL"] || "info",
  defaultMeta: process.env["AVISE_FACET"]
    ? { facet: process.env["AVISE_FACET"] }
    : undefined,

Every log line automatically includes a facet field from the environment. In DataDog, you can filter to facet:bullmq to see only background job logs, or facet:main for API logs. The log format follows [module:subModule] message [companyId:entityId].

External services map

Knock — in-app and email notifications

Knock handles all user-facing notifications: period status updates, AI chat summary, task review alerts, scheduled entry failures. Workflow templates live in the knock/ workspace (YAML definitions). The backend calls triggerNotification(workflowId, { recipients, data }) from avise-api/src/notifications/.

QBO Sync — QuickBooks Online integration

A separate workspace (qbo-sync) with its own Dockerfile and release pipeline. Runs as a separate Kubernetes service. Syncs journal entries, accounts, dimensions, and vendors from QuickBooks to Avise. Triggered by webhooks from QuickBooks or by periodic polling.

Redis + BullMQ — background job queues

BullMQ queues are used for email sending, task auto-review, and other async work. The bullmq facet of avise-api connects to Redis and processes these queues. Redis connection is configured via REDIS_URL.

SpiceDB (Authzed) — fine-grained authorization

All authorization checks go through SpiceDB. The schema is defined in avise-api/authorization-schema-test.yaml and validated in CI via authzed/action-spicedb-validate. API endpoints call companyAuthorization.checkAnyCompanyPermission() before processing requests.

Argo Workflows — long-running async jobs

Complex multi-step processes (bulk period open, schedule creation) are submitted as Argo Workflow jobs. The REST API triggers an Argo job and returns immediately. The workflow facet of avise-api executes the actual work steps as Kubernetes pods, tracked via the operation-tracking workspace.

AWS S3 — file storage

All user-uploaded files and AI-processed documents are stored in S3. Presigned URLs give the frontend temporary direct-upload access. File metadata (key, filename, content type) is stored in the PostgreSQL files table. The avise-file-indexing workspace processes files from S3 for semantic search.

MCP Servers — AI tool extension

External tools for the AI Chat are connected via the Model Context Protocol. MCP servers are configured via MCP_SERVERS env var (JSON). At startup, McpServerAdapter.initializeMcpServers() connects to each server and registers its tools. Supports stdio, SSE, streamable-HTTP, and WebSocket transports.
